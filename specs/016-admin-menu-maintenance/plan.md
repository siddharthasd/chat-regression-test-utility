## Summary

Add an Admin dropdown to the navbar (consolidating the existing Users link and a new
Job Maintenance link) and implement `GET /admin/maintenance` (stats panel) and
`POST /admin/maintenance` (clear-all-terminal-jobs + SQLite VACUUM). No new database
tables or migrations are required — all data lives in the existing `job` table.

## Key Design Decisions

### 1. Two new `JobRepository` methods

`count_all() -> int` and `count_clearable() -> int` — lightweight `SELECT COUNT(*)`
queries that the maintenance route calls to populate the stats panel. These mirror the
predicate already used in `delete_all_clearable()` so the two are always in sync.

```python
def count_all(self) -> int:
    return self._session.scalar(select(func.count()).select_from(Job))

def count_clearable(self) -> int:
    return self._session.scalar(
        select(func.count()).where(
            Job.status.in_([JobStatus.FAILED.value, JobStatus.CANCELLED.value])
            | ((Job.status == JobStatus.COMPLETED.value) & (Job.failed_count > 0))
        )
    )
```

### 2. VACUUM via raw `sqlite3` connection

SQLAlchemy's engine has `enable_transactional_ddl` which listens for `connect` and
`begin` events and auto-emits `BEGIN`. SQLite refuses to run `VACUUM` inside a
transaction. To avoid this, the maintenance route opens a raw `sqlite3` connection
directly, independent of SQLAlchemy's event system:

```python
import sqlite3
from harness.persistence.engine import resolve_db_path

def _vacuum_db() -> None:
    path = str(resolve_db_path())
    conn = sqlite3.connect(path)
    try:
        conn.execute("VACUUM")
    finally:
        conn.close()
```

This is safe because the delete transaction has already committed before `_vacuum_db`
is called, so there are no open write transactions.

### 3. DB file size via `os.path.getsize`

```python
import os
from harness.persistence.engine import resolve_db_path

def _db_size_mb() -> float | str:
    try:
        return round(os.path.getsize(resolve_db_path()) / (1024 * 1024), 2)
    except OSError:
        return "unknown"
```

Called twice in the POST handler: once before the delete/vacuum (size_before) and
once after (size_after). Both values are passed to the flash message.

### 4. Admin dropdown in `base.html`

The existing standalone `Users` nav item (inside `{% if auth_enabled and current_user %}`)
is replaced with a Bootstrap dropdown named "Admin", visible when the user is an admin
(or auth is disabled — synthetic admin always has `role == "admin"`):

```html
{% if not auth_enabled or (current_user and current_user.role == 'admin') %}
<li class="nav-item dropdown">
  <a class="nav-link dropdown-toggle px-3" href="#" role="button"
     data-bs-toggle="dropdown" aria-expanded="false">Admin</a>
  <ul class="dropdown-menu dropdown-menu-dark" style="background:#283593">
    <li><a class="dropdown-item" href="{{ url_for('admin_maintenance') }}">Job Maintenance</a></li>
    <li><hr class="dropdown-divider" style="border-color:#3949ab"></li>
    <li><a class="dropdown-item" href="{{ url_for('admin_users') }}">Users</a></li>
  </ul>
</li>
{% endif %}
```

The condition `not auth_enabled or (current_user and current_user.role == 'admin')`
handles both modes:
- Auth disabled → always show (synthetic admin)
- Auth enabled → show only for admin role

### 6. Confirmation dialog via JavaScript `confirm()`

The form's submit button uses an `onclick` handler:

```html
<button type="submit"
        onclick="return confirm('This will permanently delete ' + {{ clearable_jobs }} + ' clearable jobs and compact the database. Continue?')">
  Clear &amp; Vacuum
</button>
```

This is client-side only — the server does not re-confirm. The JS `confirm()` returns
`false` on cancel, which prevents form submission.

## Test Strategy

`tests/integration/test_admin_maintenance.py` — uses the same fixture pattern as
`test_admin_users.py` (monkeypatched DB path, auth disabled, `TestClient`).

Tests to cover:
- `GET /admin/maintenance` renders with correct stat fields present
- Stats reflect seeded job data (total_jobs, clearable_jobs)
- DB size is a positive float
- `POST /admin/maintenance` with zero clearable jobs → flash, zero deleted
- `POST /admin/maintenance` with N clearable jobs → flash shows N deleted, page reloads with clearable=0
- Successful completed jobs are not deleted
- Admin dropdown appears in rendered nav HTML
- Standalone "Users" nav item is gone from rendered HTML
- Non-admin route protection is enforced (returns 403 when auth enabled + user role)
