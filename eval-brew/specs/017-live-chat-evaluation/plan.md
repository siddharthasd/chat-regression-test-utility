# Implementation Plan: Live Chat & Real-Time Evaluation

**Branch**: `017-live-chat-evaluation` | **Date**: 2026-06-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/017-live-chat-evaluation/spec.md`

## Summary

Adds a real-time, interactive live chat subsystem to EvalBrew. Testers create a dedicated Chat Session (with an encrypted test-credential pair), then converse with a registered SSE-capable connector while simultaneously observing streaming evaluation output from a registered SSE-capable evaluator — all in a split-pane browser UI rendered with GitHub Flavored Markdown and sanitised HTML. The connector and evaluator are invoked server-side; all streaming hops use Server-Sent Events (connector→server→browser for chat tokens, evaluator→server→browser for evaluation events). Sessions are persistent, resumable indefinitely, exportable at any time, and scoped to the owning user.

Implementation spans four new ORM models, one Alembic migration, a new `harness.chat` domain package (session service, turn service, stream orchestrator, per-turn asyncio event bus), a new `harness.ui.chat_session` UI module (5-step wizard, session list, split-pane chat interface, per-turn SSE endpoint, export routes), and targeted extensions to the dashboard, admin maintenance, and registration forms.

## Technical Context

**Language/Version**: Python 3.11

**Primary Dependencies**:
- FastAPI 0.115+ — async SSE routes, `BackgroundTasks`
- SQLAlchemy 2.0 · Alembic — ORM, migrations
- httpx ≥ 0.27 — async streaming HTTP client (already in `pyproject.toml`)
- cryptography / Fernet — credential encryption (`harness.persistence.encryption`)
- Jinja2 — server-rendered templates (no bundler)
- marked.js v14 via CDN — GFM rendering in-browser (no bundler)
- DOMPurify v3 via CDN — client-side HTML sanitization

**Storage**: SQLite single-file; Alembic migration 0005 adds 4 new tables and 2 new columns on existing tables

**Testing**: pytest; in-memory SQLite fixtures (`StaticPool`); existing `conftest.py` fixture patterns

**Target Platform**: Windows server (LAN); Gunicorn + UvicornWorker + Nginx

**Project Type**: Web application — server-rendered Jinja2 templates + inline JS

**Performance Goals**:
- First connector token visible within 500 ms of connector beginning response (SC-002)
- Chat interface (50 turns) loads in < 2 seconds (SC-010)
- Session export for 20 turns completes in < 3 seconds (SC-004)
- Admin bulk-delete of 1,000 sessions completes in < 10 seconds (SC-008)

**Constraints**:
- No frontend build step — marked.js and DOMPurify loaded via CDN `<script>` tags
- Single-file SQLite (acceptable for 50–80 users; per deployment assumptions)
- Mixed sync/async FastAPI routes — SSE and pipeline routes async; all existing routes remain sync
- Credentials encrypted via existing `encrypt_credential` / `decrypt_credential` utilities

**Scale/Scope**: 50–80 concurrent users; sessions accumulate 100+ turns; ≤ 1,000 sessions targeted for admin bulk-delete
