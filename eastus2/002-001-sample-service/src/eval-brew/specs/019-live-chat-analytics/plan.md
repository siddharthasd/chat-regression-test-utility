# Implementation Plan: Live Chat Session Analytics

## Summary

Adds a dedicated analytics page at `GET /chat/sessions/{session_id}/analytics` for live chat sessions. The page surfaces the same analytical report defined for batch jobs in feature 018 — per-parameter stat tiles, CSS histogram with ±1σ bands, verdict distributions, a collapsible guide, and per-tile tooltips — by mapping `ChatSession → ChatTurn → ChatTurnResult.final_evaluation_result` to the shared `RunAnalytics` engine introduced in 018. A new Turn Explorer table lists all completed and failed turns with scores, verdicts, and row expand. Two new download routes (long-format CSV and nested JSON) are always available (no terminal-state restriction). An "Analytics" link is added to the session interface page.

No new ORM models and no database migration are required. The only new code paths are: a route handler, a view mapper, a template, CSS additions, and integration tests.

**Dependency**: Feature 018 must be implemented first. This feature imports `RunAnalytics`, `ScoreEntry`, and `compute_analytics` directly from `harness.ui.detail.analytics`.

## Technical Context

**Language/Version**: Python 3.11

**Primary Dependencies**:
- FastAPI 0.115+ — existing web framework
- SQLAlchemy 2.0 — existing ORM (read-only; no new tables)
- Jinja2 — existing server-rendered templates (no bundler)
- Bootstrap 5 (existing CDN) — sidebar, tooltips
- Python `statistics` / `math` stdlib — via shared `RunAnalytics` engine (018); no direct use in 019
- Vanilla JS inline `<script>` — scrollspy, guide collapse, `window.print()`, Blob downloads
- `harness.ui.detail.analytics` — **shared engine from 018**; imported directly

**Storage**: No new tables. No Alembic migration. Reads from existing `chat_turn`, `chat_turn_result`, `chat_session` tables.

**Testing**: pytest; in-memory SQLite fixtures (`StaticPool`); existing `conftest.py` patterns

**Target Platform**: Windows server (LAN); existing FastAPI + UvicornWorker deployment

**Project Type**: Web application — server-rendered Jinja2 templates + inline JS

**Performance Goals**:
- Analytics page loads in < 3 seconds for sessions with ≤ 5,000 turns
- CSV/JSON download initiates within 2 seconds

**Constraints**:
- 018 must be implemented before 019 (shared engine dependency)
- Analytics computation is synchronous, server-side at page load
- Sessions with `total_turn_count > 5,000` skip analytics computation (FR-012)
- Downloads are always available — sessions have no terminal state (FR-021)
- In-progress turns excluded from Turn Explorer and all downloads
- Access restricted to session owner (019 FR-002); admins cannot view other users' analytics

**Scale/Scope**: 50–80 concurrent users; sessions typically accumulate < 200 turns; 5,000-turn guard is a safety net
