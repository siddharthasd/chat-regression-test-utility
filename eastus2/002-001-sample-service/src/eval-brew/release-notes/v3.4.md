# EvalBrew v3.4 — Release Notes

**Released:** 2026-08-10

## Overview

v3.4 delivers the Backlog Layer (BL-001 through BL-005) — a set of traceability, transparency, and data-quality improvements built on top of the v3.3 evaluation foundation. It also closes a critical security gap where Kubernetes pods could silently regenerate their encryption key on restart, permanently corrupting all stored credentials.

---

## New Features

**KB Source Traceability (BL-001)**
Every result row in both the detail view and all download formats now carries the KB source column (document or chunk reference) returned by the evaluator. Teams can trace any score back to the exact knowledge-base fragment the LLM drew on.

**Flat CSV and XLSX Downloads (BL-002)**
Two new download formats join the existing per-dimension export:

- **Flat CSV** — one row per utterance, all dimensions side-by-side, streaming directly to the browser without buffering the full result set in memory.
- **Flat XLSX** — same layout in an Excel workbook, styled with alternating row shading and frozen header row.

Both formats include dynamic dimension columns (only the dimensions the evaluator actually declared) and the KB source column.

**Stakeholder-Friendly Column Headers (BL-003)**
Column labels in every CSV and XLSX download are now human-readable. `dim_accuracy_score` becomes `Accuracy: Score`; `dim_accuracy_result` becomes `Accuracy: Result`; and so on. Data-dictionary sheets in XLSX exports use the same labels.

**Verdict Aggregation Transparency (BL-004)**
Evaluators can now declare per-dimension pass/warn/fail thresholds in their registration. When thresholds are set:

- The registration detail view shows a threshold table (Dimension / Pass ≥ / Warn ≥).
- The job detail view shows a ⓘ tooltip next to each dimension score.
- Every XLSX export gains a **Data Dictionary** sheet documenting the rollup rule and any declared thresholds.

Rollup rule (harness convention, not computed): fail if any dimension fails; warn if any warns and none fails; pass only if every dimension passes.

**Dimension Declaration Constraints (BL-005)**
When an evaluator declares scoring dimensions, score-scale min and max are now required. The registration form enforces that `scale_min < scale_max`, dimensions are limited to 10, and dimension names follow a safe identifier pattern. Live-chat analytics now use the evaluator's declared scale when computing normalised scores, matching the behaviour of batch job analytics.

## Security

**Kubernetes Encryption Key Guard**
Previous releases added `HARNESS_MASTER_KEY` env-var support but left a silent fallback: if the env var was absent (e.g., a misconfigured Kubernetes Secret or a deployment update that dropped the mount), the harness would generate a new ephemeral Fernet key per pod and per restart, permanently making all stored credentials unreadable.

v3.4 closes this gap:

- The harness now detects Kubernetes by the `KUBERNETES_SERVICE_HOST` env var (automatically set in every pod) and raises a clear `RuntimeError` at startup when `HARNESS_MASTER_KEY` is not provided, refusing to generate an ephemeral key.
- Key validation runs **at startup** (not on the first credential request), so the pod fails liveness checks immediately rather than corrupting data silently.
- On local dev, generating a new key file now emits a `WARNING` log entry so the event is always visible.

**Operator action required:** ensure `HARNESS_MASTER_KEY` is mounted from a Kubernetes Secret in your Deployment manifest. See the deployment guide for the recommended `secretKeyRef` pattern.

## Bug Fixes

- **Auth** — RBAC email lookup now handles pre-linked OID records and accepts `unique_name` / `preferred_username` SSO claims in addition to `upn`, preventing login failures for certain Azure AD configurations.
- **Encryption** — `HARNESS_MASTER_KEY` env var is now accepted case-insensitively (`harness_master_key`) to match cloud secret naming conventions.
- **SSE proxy** — live-chat sessions no longer fail silently behind proxies that buffer streaming responses; the SSE endpoint now sets `X-Accel-Buffering: no` and appropriate cache-control headers.
- **CDN elimination** — `marked.js` and `DOMPurify` are now served from the application's own static assets, removing the external CDN dependency and the associated CSP complexity.
- **Score computation** — sentinel `ScoreEntry` objects (used to represent missing or non-numeric scores) now carry `is_numeric_score=False`, preventing them from skewing the overall mean score calculation. String scores that parse as floats (e.g., `"0.75"`) are correctly treated as numeric.
- **Legacy mean** — the overall mean score filter now respects `is_numeric_score` on all code paths, including the legacy (non-dimension-declared) path.

## UX

- Job sessions page: replaced the **Completed** column with a **Duration** column (wall-clock time for the run), making it easier to spot slow evaluations at a glance.
- Job creation wizard: SSE-only connectors and evaluators are now excluded from the batch-job dropdowns, preventing misconfigured job submissions.

## Performance & Testing

- Download benchmark expanded to cover two evaluator profiles and 2,000-utterance result sets; p95 streaming latency confirmed within acceptable bounds.
- 7 code-review findings across BL-001/002/003 and 7 across BL-004/BL-005 resolved before tagging.
- 2 new encryption tests cover the Kubernetes key-guard paths.
